## 1. 产品概述

### 1.1 产品定位
面向 K12 学校教师（兼顾学生、家长、学校管理者）的「资源 + AI + 教学全流程」平台：
**找资源 → 备课（AI 生成教案/课件）→ 授课（互动课堂）→ 作业/考试（组卷、答题卡、扫描阅卷）→ 学情分析 → 错题重练 → 教研交流**，并以「金榜币 + 成长等级」驱动用户活跃和变现。

### 1.2 用户角色

| 角色 | 说明 | 状态 |
|---|---|---|
| 游客（visitor） | 自助注册用户，归属「访客学校（默认）」，可用资源、备课、AI 等基础功能 | ✅（本次实测角色） |
| 教师 | 学校导入的教师账号，可用考试阅卷、学情 | 🔒 |
| 班主任 / 年级主任 | 教师身份扩展，查看本班/本年级学情 | 📘 |
| 学校管理员 | 学校管理（学年/年级/班级/师生导入）、数据中心 | 📘 🔍 |
| 学生 | 学生论坛「学海共渡」中已出现学生发帖；学生端未展示 | 🔍 |
| 家长 | 手册提到「智教智学家长端」微信小程序 | 📘 |
| 平台运营 / 内容审核 | 资源审核、店铺审核、征集审核、敏感词、反馈处理 | 🔍（agent 前端含后台菜单文案）➕ 独立运营后台 |
| 区域教研员 / 教育局 | 区域联考（考试中心文案提及） | ➕ P2 |

- 「身份切换」（头像菜单）✅ 入口存在，用于同一账号在多身份间切换（教师/班主任/管理员等）。
- ➕ P0 **角色权限矩阵后台可配置**：菜单由 `getWebRouters` 下发，需在运营后台可视化配置角色-菜单-按钮权限。

## 2. 通用 / 全局功能

### 2.1 账号与登录

| 功能点 | 业务逻辑 | 状态 |
|---|---|---|
| 账号密码登录 | 登录名 + 密码 + **算术图形验证码**（如 `3*4=?`）；可勾选「记住密码」 | ✅ |
| 验证码登录 | 手机号 + 短信验证码（`/system-center/sms/code`） | ✅ 入口 |
| 微信扫码登录 | 微信开放平台 `wxLogin.js` 二维码；未绑定时走 `social/bind` 绑定流程 | ✅ 入口 |
| 注册账户 | 手机号注册，注册即送 **500 金榜币**，自动归属「访客学校（默认）」，角色=游客 | ✅ |
| 修改密码 | 方式一：手机号+验证码+新密码；方式二：原密码修改（`updatePwd` / `updatePwdByPhone`） | ✅ |
| 退出登录 | 头像菜单「退出登录」，服务端 token 失效 | ✅ |
| 单点登录到 AI 平台 | 主站调用 `auth/getTicket` 获取一次性 ticket → 跳转 `agent.sjjbai.com/index?ticket=xxx` → agent 调 `auth/ssoLogin` 换取 agent token（有效期 7 天） | ✅ |
| 学科网账号绑定 | OAuth2 跳转 `sso.zxxk.com`，扫码关联学科网账号；`xkw/bind-status` 查询绑定状态 | ✅ 入口（实测网络超时 ⚠️） |
| 个人资料/头像 | `user/profile`、`profile/avatar` | 🔍 无独立「个人资料编辑」页面 |
| 身份切换 | 头像菜单 → 身份切换（下拉多身份） | ✅ 入口 |
| ➕ 忘记密码 | 登录页无「忘记密码」入口，只能登录后改密 | ➕ **P0** |
| ➕ 账号注销 | 个人信息保护法要求提供注销 | ➕ P1 |
| ➕ 登录设备管理 / 异地登录提醒 | 查看在线设备、强制下线 | ➕ P2 |
| ➕ 首次登录强制改密 | 学校导入教师默认密码 `123456`（手册），必须首登改密 | ➕ **P0** |
| ➕ 登录失败锁定 | N 次失败锁定 + 滑块/行为验证码（算术验证码强度过低） | ➕ P1 |
| ⚠️ ticket 明文放在 URL | SSO ticket 出现在地址栏/浏览器历史/Referer，且 agent 首页存在 http 访问记录 | ⚠️ P1（ticket 需一次性+短时效+全站 HTTPS） |

### 8.2 权限模型设计

```
用户 User ──< 用户身份 UserIdentity >── 角色 Role ──< 角色菜单 >── 菜单/按钮 Menu(perms)
   │              │(租户tenant, 学校dept, 身份类型, 是否默认)        │
   │              └── 数据范围 DataScope：全部 / 区域 / 本校 / 本年级 / 本学科组 / 本班 / 仅本人
   └── 账户 Account（金榜币、经验、等级）——按「自然人」唯一，不随身份切换
```

| 规则 | 说明 | 状态 |
|---|---|---|
| R1 菜单权限 | 前端菜单和路由由 `getWebRouters` 按当前身份下发；按钮通过 `perms` 控制显示 | ✅（菜单）🔍（按钮） |
| R2 数据权限 | 查询接口按 dataScope 自动拼接过滤条件。例如班主任查学情，只能看本班；任课老师只能看「所教班级 × 所教学科」 | 🔍 ➕ 需要明确定义 |
| R3 多身份 | 同一个手机号可以同时是 A 校的班主任、B 校的任课老师，也可以是某学生的家长。用「身份切换」来切换当前上下文 | ✅ 入口 |
| R4 身份默认 | 登录时进入上次使用的身份，或标记为默认的身份 | ➕ P1 |
| R5 游客升级 | 游客教师申请加入学校：输入学校邀请码，或由管理员导入 → 审核通过后变成该校教师，个人备课数据随账号保留 | ➕ **P0**（现在游客没有任何途径加入学校） |
| R6 离职 | 教师「批量离职」后失去学校数据权限；个人备课和资源归个人所有；在校期间产生的班级数据归学校 | 🔍 ➕ 需要明确归属规则 |
| R7 学生数据隔离 | 学生只能看到自己的数据；家长只能看到已绑定的孩子；跨校数据完全隔离（tenant 级） | ➕ **P0** |
| R8 越权防护 | 后端必须按身份上下文二次校验，不能只靠前端隐藏菜单（隐藏路由 `/edu-affairs` 可以直接访问，这一点必须保证接口层拦截） | ⚠️ **P0** |
| R9 未授权提示 | 无权限时统一给出 403 提示和申请指引（见 2.2 ⚠️） | ⚠️ P0 |

### 8.3 身份交接与权限撤销规则（v1.1 新增）➕ **P0**

总原则：**数据跟着组织走，作品跟着人走**。身份变化后，按下表立即生效。下载链接、导出文件、缓存的报告也要同时失效。

| 事件 | 列表与报表 | 原卷图片 | 报告下载 / 导出文件 | AI 学情查询 | 个人备课 | 校本已发布内容 | 已有成绩数据 |
|---|---|---|---|---|---|---|---|
| 切换身份 | 只显示当前身份范围内的数据 | 同左 | 同左 | 按当前身份 | 不受影响 | 不受影响 | 不受影响 |
| 任课教师换班或换学科 | 新班可见；旧班历史数据**只保留自己批阅过的作业 / 考试的只读权限**，保留到学年结束 | 旧班不可见 | 旧班已导出的链接失效 | 只能查新班 | 不受影响 | 不受影响 | 归学校 |
| 班主任更换 | 新班主任可以看本班全部历史；旧班主任失去本班全科权限 | 同左 | 同左 | 同左 | 不受影响 | 不受影响 | 归学校 |
| 教师离职（批量离职） | 全部学校数据立即不可见 | 不可见 | 失效 | 不可见 | **归个人，账号保留**，身份退回游客 | 留在学校，作者显示「已离职」 | 归学校 |
| 教师转校 | 同离职，然后在新学校建新身份 | — | — | — | 归个人 | 留在原校 | 归原校 |
| 学生转班 | 新班老师可以看该生**全部历史**；旧班老师在旧班的统计里保留该生的历史记录（只读） | 新班可见 | — | 按新班 | — | — | 跟着学生 |
| 学生转校 / 毕业 | 原校归档只读；新校看不到原校数据 | 原校归档 | — | — | — | — | 原校归档 |
| 家长解绑 | 立即看不到该学生的任何数据和通知 | 不可见 | 失效 | 不可见 | — | — | — |
| 游客加入学校 | 获得学校身份范围；游客期的个人数据保留在个人名下 | — | — | — | 归个人 | — | — |

- 验收要求：每个事件都要验证**直接拼接口地址**也访问不到被撤销的数据（不能只是前端菜单隐藏）。
- 学生论坛：快照能证明有内容可以看到，但学生登录、发帖、审核这条链路**没有证据**，需要单独确认。

## 9. 分角色功能深度分析（前台 + 管理能力）

每个角色按「角色画像 → 核心场景 → 功能清单 → 关键业务规则 → 缺失项」来写。

### 9.1 游客教师（自注册个人用户）✅ 本次实测身份

- **画像**：自己注册试用的老师、培训机构老师，没有学校归属。
- **核心场景**：找资源、AI 备课、AI 出题和批改、积累金币。
- **可用功能**（实测）：首页、资源中心 7 个模块、独立备课（含智能备课）、互动授课列表、金榜杏坛、个人中心全部页签、AI 平台全部智能体（扣金币）、考试中心和答题卡（空数据）。
- **不可用**：考试阅卷、教务教研、学习中心、作业组卷、试卷组卷、授课。
- **业务规则**
  - 注册送 500 币。AI 先使用后扣费。资源按等级特权和金币下载。
  - 数据只属于本人，不进入任何学校的数据池。
- **缺失**
  - ➕ **P0 申请加入学校**：搜学校、填邀请码、上传教师资格信息 → 学校管理员审核。
  - ➕ P1 首次登录完善资料：任教学段、学科、年级、教材版本。之后用来做默认筛选和推荐，现在每次都要手动切「高中 语文」。
  - ➕ P1 游客版功能对比和升级引导：比如「加入学校后可使用扫描阅卷、学情分析」。
  - ➕ P2 「我的班级（个人版）」：游客老师也能自建班级、录入学生名单，用 AI 批改和错题本。这是面向培训机构的场景。

### 9.2 任课教师（学校教师）📘

- **画像**：学校导入的老师，账号是手机号，默认密码 [已脱敏]。绑定「年级 × 班级 × 学科」，可以教多个班。
- **核心场景**：备课 → 授课 → 布置作业 → 扫描批阅 → 讲评 → 学情 → 错题重练。

| 场景 | 功能 | 规则 | 状态 |
|---|---|---|---|
| 备课 | 独立备课、智能备课、校本资源、集体备课参与 | 备课资料归个人；可以分享到学校空间 | ✅ 🔍 |
| 授课 | 互动授课、手机遥控、随机点名、随堂测 | 点名名单取自所教班级的学生 | 🔒 🔍 |
| 作业 | 题库组卷 → 生成作业 → 答题卡 → 试卷列表点「布置作业」（名称、线上/线下、完成时间、行政班/教学班、指定学生） | 只能布置给自己所教的班级和学科 | 🔍 前端流程完整（见 3.3）。⚠️ **学年写死为 2025**：新学年取不到班级，或者把作业挂到错误的学年 |
| 批阅 | 扫描、客观题自动判、主观题线上批阅、作文 AI 批阅 | 只能批阅本人布置的作业，或分配给自己的阅卷任务 | 📘 |
| 讲评 | 作业讲评、大屏演示、类题推送 | | 📘 |
| 学情 | 所教班级 × 本学科：班级学情、个人学情 | 看不到其他学科的成绩 | 📘 |
| 错题 | 所教学生的错题组卷 | | ✅ 入口 |
| 教研 | 杏坛、听评课记录、公开课 | 听课记录和评价写入教研统计 | 🔍 |
| AI | 全部智能体 | 学校购买套餐后应该免金币或按配额使用 | ➕ P1 |

- ➕ **P0 「我的班级」工作台**：所教班级列表 → 进入班级可看学生、作业、考试、学情。现在没有以班级为中心的入口。
- ➕ P1 作业布置还缺的属性：是否公布答案、什么时候公布、迟交和补交规则、拍照提交方式（已有的字段：发布对象、完成时间、线上/线下）。
- ⚠️ P0 待验证：学生端能不能收到布置的作业（素材里没有学生端证据）。
- ➕ P1 代课 / 临时授权：比如请假期间，把班级权限临时授给其他老师。

### 9.3 班主任 📘

- **在任课教师的全部权限之上，额外增加：**
  - **本班全学科**学情。成绩下降学生的判定是「连续 3 次考试下降」，临界生是「及格线上下 5%」。
  - 本班学生信息维护：编辑学生信息、学号、调座位（➕）。
  - 本班考试和成绩发布到家长端。
  - 家校沟通：通知、学生评语、家长会发言稿。AI 侧前端有「家校沟通 / 学生评语 / 班主任工作计划 / 期末总结 / 主题班会教案」的文案。🔍
  - 管理学生论坛中本班的帖子。
- **规则**：一个班只能有一个班主任；更换班主任时，历史数据权限跟着「班级」走。
- **缺失**
  - ➕ **P0 班级学情总览页**：各科均分、排名、预警学生、作业提交率，一屏看全。
  - ➕ P1 学生个人档案：历次成绩、错题、作文进步、评语、家长绑定状态。
  - ➕ P1 家长绑定管理：查看哪些家长已绑定，生成绑定邀请码。
  - ➕ P2 德育 / 考勤 / 评价（综合素质评价）。

### 9.4 年级主任 📘

- 本年级全部班级、全部学科：学情、考试、教师。
- 年级学情（手册 6.1）：班级成绩对比、学业等级分布、临界生、优秀生与学困生对比。
- 创建年级统考 → 分配阅卷任务（按题块分给老师）→ 监控阅卷进度 → 发布成绩。
- 本年级教师的备课量和扫描量统计（只读）。
- 规则：一个年级只有一个年级主任。
- ➕ P1 阅卷进度看板：按题块、按老师显示完成率，可以催办。
- ➕ P1 分层分班辅助：按成绩分层推荐分班。

### 9.5 教研组长 / 备课组长 🔍 ➕

## 11. 核心业务流程与状态机

### 11.1 AI 智能体调用与计费 ➕ P0

**统一口径**：对用户的说法保持「先使用再扣费」；系统内部实现是**提交时冻结预估金额，完成后按实际结算**（用户看到的是「预计消耗 N 币」，结果出来后才真正扣）。两种说法在页面文案和规则里只能用这一套。

```
提交 → 生成任务ID → 余额校验(不足→提示充值，不创建任务)
     → 冻结预估金额(流水：冻结) → 执行
     → 结算：按下表 → 流水：扣费/解冻 → 个人账单与运营流水用同一任务ID对账
```

| 情况 | 是否收费 | 解冻时机 | 结果保留 | 用户提示 |
|---|---|---|---|---|
| 成功 | 按实际用量收费（不超过预估金额） | 结算时退回差额 | 永久保留在历史记录 | 显示本次消耗 |
| 系统失败、工具故障、超时 | **不收费** | 立即全额解冻 | 保留失败记录（可以重试） | 「服务暂时不可用，未扣费」，不暴露内部细节 |
| 空结果（没检索到、识别失败） | **不收费** | 立即 | 保留 | 说明原因和改进建议 |
| 内容审核拦截 | 不收费 | 立即 | 不保留内容 | 提示内容不合规 |
| 用户主动停止 | 按已生成的部分收费；生成不足 10% 的不收费 | 停止时 | 保留已生成的部分 | 显示本次消耗 |
| 批量任务部分成功（比如批改 30 篇，失败 3 篇） | 只收成功部分的费用 | 任务结束时 | 成功和失败分别列出 | 「成功 27，失败 3（未扣费），可重试失败项」 |
| 重试 | 重试的是同一个任务 ID 下的子任务，**幂等，不会重复扣费**；只有成功的那次收费 | — | 关联原任务 | — |
| 重新生成（用户主动） | 算新任务，正常收费 | — | 新旧结果都保留 | 提示会再次消耗 |

验收：每个任务在个人消费记录和运营流水（`coinFlow`）里各有一条，金额一致，都能用任务 ID 查到。

### 11.2 智能备课（主站）✅ + ➕
```
选择目录节点 → 输入主题(教材/课目/要求) → AI生成大纲(流式)
 → [➕编辑大纲] → 选模板 → 生成PPT → 存入目录 → WPS编辑/下载/授课/分享
 → 成长奖励(+20经验 +10币，每次)
```

### 11.3 资源生命周期
```
平台资源： 草稿 → 待审核 → 已上架 ⇄ 已下架
                     └→ 驳回(原因) → 修改后重新提交
征集投稿： 已提交 → 审核中 → 通过(纳入平台资源+奖励) / 驳回
校本资源： 教师分享 → 教研组长审核 → 学校空间发布(范围：全校/年级/学科组)
```

### 11.4 店铺与提现
```
开店：申请(实名) → 审核 → 营业中 ⇄ 冻结(违规) → 关闭
提现：申请 → 财务审核 → 打款中 → 已到账 / 失败(退回余额)
```

### 11.5 作业与考试状态机（v1.1 拆分为三类，补异常）➕ **P0**

**A. 纸质作业**（从试卷布置，方式选「线下」）
```
已布置 → 收集中 → 扫描中 → 批阅中 → 批阅完成 → [讲评/错题] → 归档
```
| 异常 | 规则 |
|---|---|
| 迟交 | 截止时间过后仍然可以扫描，标记为「迟交」，计入统计但单独标出；教师可以关闭迟交 |
| 补交 | 「批阅完成」后再扫进来的答卷，进入「补交待批」，批完后自动重算统计 |
| 未交 | 截止后没交的算「未交」，不计入均分，计入提交率 |
| 重复扫描 | 按 6.2 的规则处理（默认保留最新一份，人工批阅过的分数不被覆盖） |
| 异常卷（学号缺失或不存在） | 进入「异常作业」，人工分配后进入正常流程 |

**B. 线上作业**（方式选「线上」）
```
已发布 → 作答中(学生端) → 截止 → 批阅中(客观自动/主观人工或AI) → 已批阅 → [公布答案] → 归档
```
迟交和补交规则同 A；学生提交后，截止前可以撤回重交（教师可配置）。

**C. 正式考试**
```
草稿(建考/考生/答题卡) → 待扫描 → 扫描中 → [完成扫描] → 阅卷中 ⇄ 暂停阅卷
 → 阅卷完成 → 临时成绩(核对/修改/导入) → [➕成绩审核] → 已发布成绩
 → 已发布学情 → 归档
```
| 异常 | 规则 |
|---|---|
| 缺考 | 考生管理里标记缺考或免考；不计入均分和排名，单独统计人数 |
| 问题卷 | 阅卷老师上报（图片不清、答错位置、疑似雷同）→ 题组长或管理员处理 → 处理完成后回到阅卷队列 |
| 阅卷重开 | 「重新阅卷」可以针对某个学生的某个学科、某道题：已发布的要先撤回，或者走更正流程 |
| 成绩更正（发布前） | 在临时成绩里修改，记录修改人、原分、新分、原因 |
| 成绩更正（发布后） | 修改 → 重算 → **自动给受影响的学生和家长发「成绩更正」通知**（列出原分和新分），教师端留更正记录 |
| 发布范围 | 可以按全年级 / 班级 / 学科分别发布；「设置查看对象」控制学生端和家长端能看到哪些菜单和指标（比如隐藏排名） |
| 撤回发布 | 撤回后学生端和家长端立即看不到；**已经推送出去的通知不能撤回**，再补发一条「成绩暂时撤回」通知 |
| 学情重置 | 「重置学情」会清空已经算出来的学情，需要重新发布；操作需要二次确认并留日志 |

### 11.6 订单
```
待支付 →(支付成功)→ 已支付 → [退款中 → 已退款]
       →(用户取消/超时30分钟)→ 已取消      待支付可「重新支付」(rePay)
```

### 11.7 举报处理
```
用户举报(对象/原因) → 待处理 → 审核员判定 → 成立(下架内容+处罚+通知双方) / 不成立(通知举报人)
→ 「我的举报」显示处理结果
```

### 11.8 学年升级 ➕ P0
```
管理员发起 → 校验(未完成阅卷/未发布成绩提示) → 新学年创建
 → 各年级+1、毕业年级归档 → 班级沿用/重组 → 任教关系清空待重新分配
 → 新生导入 → 切换当前学年
```

### 11.9 游客加入学校 ➕ P0
```
游客 → 申请加入(学校搜索+邀请码/证明) → 学校管理员审核
 → 通过：新增「XX学校·教师」身份(保留个人数据) → 管理员分配任教关系
 → 驳回：通知原因
```

### 11.10 家长绑定 ➕ P0
```
家长小程序 → 输入学号+姓名 + [➕班主任邀请码/手机验证]
 → 校验匹配 → 绑定(可多孩) → 班主任端可见绑定状态、可解绑
```

## 16. 待决策事项（进入开发和验收前必须定下来）

下面四项一旦定错，会直接影响数据模型和验收，**建议这一轮先定**。每项都给了建议方案，需要产品负责人拍板。

| # | 决策项 | 需要定的内容 | 建议方案 | 关联章节 |
|---|---|---|---|---|
| D1 | **作业发布与学年取值** | 学年从哪里取；跨学年的作业归属哪一年；发布对象（行政班、教学班、指定学生）怎么校验；学生端的触达方式 | 学年取学校的「当前学年」，不允许前端写死；作业归属按发布时的学年；按学期切换后，旧作业只读 | 3.3、9.2、11.5-A/B、缺陷 19 |
| D2 | **考试与成绩发布** | 要不要加成绩审核；能不能按班级或学科分批发布；发布后改分是否通知；撤回的规则；学生和家长能看到什么 | 加审核；可以分批；发布后改分必须通知；排名默认不对学生和家长显示 | 6.1、11.5-C |
| D3 | **学情统计口径** | 有效答卷范围、得分率的分母、成绩分档用 A 还是 B、边界值、缺考和未阅完的处理、跨考试比较的方法 | 按 6.6「指标口径」；分档默认用 A，学校可以自定义 | 6.6 |
| D4 | **AI 扣费与补偿** | 「先用后扣」和「冻结预估」统一成一套；失败、空结果、中止、部分成功、重试分别怎么收费；补偿方式（自动退回还是人工） | 按 11.1 规则表；一律自动退回；运营后台可以人工调账，但要审批 | 11.1、7.1、缺陷 1 |
| D5 | 答题卡版本 | 下载后改题是否生成新版本；锁定时机 | 按 6.3「版本与锁定规则」 | 6.3 |
| D6 | 身份交接 | 离职、转班、解绑之后的数据可见性 | 按 8.3 交接表 | 8.3 |
| D7 | 交易是否纳入首期 | 店铺、提现、退款要不要首期上线 | 如果首期不做交易，店铺相关功能隐藏；做交易就按 3.8 的售后规则 | 3.8 |

## 17. 关键验收用例（P0）

证据说明：标「代码存在」的能力，**全部要按本章实测通过才算现状可用**。

| 编号 | 场景 | 前置条件 | 步骤 | 预期结果 |
|---|---|---|---|---|
| AC-01 | 布置作业跨学年 | 学校当前学年设成 2026，有班级 | 从试卷布置一份作业，选班级和学生 | 能取到 2026 学年的班级；作业的学年字段是 2026；学生端能收到 |
| AC-02 | 重复扫描 | 某学生的作业已扫描，主观题已经人工批阅 | 再扫同一份 | 进「重复扫描」列表；默认保留新的一份，但人工分数不被覆盖；可以手动换回旧的一份 |
| AC-03 | 整批重新识别 | 批次里有已经人工改过的分数 | 执行重新识别 | 只更新客观题和未批阅的题；有冲突时提示教师 |
| AC-04 | 答题卡版本 | 答题卡 v1 已下载、已扫描 | 修改分值或布局 | 生成 v2；之后扫进来的 v1 纸卷仍然按 v1 识别 |
| AC-05 | 成绩发布后更正 | 成绩已发布 | 修改某个学生的成绩 | 重算报表；学生和家长收到更正通知（原分→新分）；留有更正记录 |
| AC-06 | 撤回成绩 | 已发布 | 撤回 | 学生端和家长端立即看不到；补发撤回通知 |
| AC-07 | 学情口径 | 一份试卷，题目分值不同（2 分题和 12 分题） | 计算班级平均得分率 | 等于「实得总分 ÷ 应得满分」，不等于「得分 ÷ 题数」 |
| AC-08 | 缺考和未阅完 | 有缺考、有阅卷没完成的学生 | 查看均分 | 这些人不计入均分，人数单独列出 |
| AC-09 | AI 失败不扣费 | 模拟题库工具故障 | 提一个会触发题库的问题 | 余额不变；消费记录显示「失败-未扣费」；提示里不出现内部信息 |
| AC-10 | AI 批量部分成功 | 一次批改 10 篇作文，其中 2 篇是空白图 | 提交 | 只收 8 篇的费用；2 篇失败可以重试 |
| AC-11 | 流水重试幂等 | 有一条失败的流水 | 连续点两次重试 | 最多扣一次费；两次重试都关联原任务 ID |
| AC-12 | 对账 | 任意一个 AI 任务 | 分别在个人消费记录和运营流水里查 | 用同一个任务 ID 都能查到，金额一致 |
| AC-13 | 越权（接口层） | 游客账号 token | 直接调用学情、考试、学生名单接口 | 返回 403 或空，不返回任何学校数据 |
| AC-14 | 离职撤权 | 某教师有已导出的成绩文件链接 | 管理员办理离职 | 该教师看不到学校数据，导出链接失效，个人备课仍在 |
| AC-15 | 家长解绑 | 家长已绑定孩子 | 班主任解绑 | 家长端立即看不到孩子的数据和通知 |
| AC-16 | 无权限提示 | 游客 | 点击考试阅卷、教务教研，打开 /edu-affairs | 显示 403 提示，告诉用户怎么申请权限 |
| AC-17 | 占位入口 | 任意 | 查看作业组卷、试卷组卷、更多智能体 | 入口灰显，带「即将上线」角标 |

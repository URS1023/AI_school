# 世纪金榜AI 教学平台 · Java 技术路线

> 依据：《世纪金榜AI平台-功能逻辑需求文档》v1.1（下文简称 PRD）；《金榜AI智教智学系统使用手册（修订版）》PDF 全文和 wolai 原页全部 174 张截图
> 目标：用 Java 技术栈重建或承接 A 主站、B AI 平台、C 扫描阅卷与学情三套系统，并覆盖 PRD 中的 ✅ / 🔍 / ➕ 功能
> 日期：2026-11-20

## 0. 结论先行

| 决策 | 建议 | 理由（对应 PRD） |
|---|---|---|
| 语言与运行时 | **Java 21 LTS**（启用虚拟线程） | AI 流式调用、第三方 HTTP、扫描任务都是 IO 密集型，虚拟线程能用同步写法扛高并发 |
| 基础框架 | **Spring Boot 3.5.x + Spring Cloud 2025.0 + Spring Cloud Alibaba**；等生态跟上后再升 Boot 4 | 现网证据（`getWebRouters`、`sys_*` 字典、`monitor:operlog:list`、`roles[].dataScope`、`tenantId`）表明现系统就是**类 RuoYi 架构**，沿用同一套思路迁移成本最低 |
| 脚手架 | **RuoYi-Cloud-Plus**（或 RuoYi-Vue-Plus 多模块版） | 自带多租户、RBAC、数据权限、字典、操作日志、OSS、短信、SnailJob，直接覆盖 PRD 第 2、8、10 章约 40% 的底座需求 |
| 架构形态 | **按领域拆 8 个服务 + 网关**，不过度拆分 | 考试阅卷、AI、资源检索的负载特征差别大，需要独立扩缩容；但团队规模有限，服务数量要控制 |
| AI 接入 | **Spring AI**（模型抽象、工具调用、RAG）+ 自研「智能体运行时」和计费 | PRD 11.1 的冻结/结算/失败退费是业务核心，不能交给框架 |
| 图像识别 | **Python 识别服务**（OMR / OCR / 版面分析）+ Java 编排 | Java 在答题卡识别、手写 OCR 上生态弱；用 MQ 解耦，Java 只做任务调度和结果入库 |
| 数据层 | MySQL 8 主库 + Redis + RocketMQ + Elasticsearch + 对象存储 + Doris（学情分析）+ 向量库（Milvus 或 pgvector） | 资源 54.8 万条需全文检索；学情是 OLAP 场景，不能压在业务库上 |

**一句话路线**：以 RuoYi-Cloud-Plus 为底座先补齐「账号 / 多租户 / 权限 / 金币账户」，再做「资源 + 题库 + 备课」，并行建设「AI 中台」，最后接「考试阅卷 + 学情」和学生、家长端。

## 3. 关键技术方案（按 PRD 的 P0 难点）

### 3.1 统一账号、SSO 与多身份（PRD 2.1、8.1–8.3）

**模型**：`User`（自然人，按手机号唯一）1:N `UserIdentity`（租户 + 身份类型 + 角色）；`Account`（金币/经验）挂在 User 上，不随身份切换。

**Token 设计**：
- 登录后 token 绑定 `userId + 当前 identityId`；身份切换 = 校验该身份属于本人 → **重新签发 token**（不在旧 token 上改字段，避免缓存的权限残留）。
- Token 会话里存 `tenantId / identityId / roleKeys / dataScope / deptId / 任教关系摘要`，由网关解析后放入请求头，下游用 `IdentityContext` 读取。

**SSO（修复 PRD ⚠️ ticket 明文问题）**：
```
主站 → POST /auth/ticket          生成 ticket = 随机 32 字节，Redis SET ticket:{t} {userId,identityId} EX 60
     → 302 agent.sjjbai.com/sso?ticket=t   （全站 HTTPS；Referrer-Policy: no-referrer）
agent → POST /auth/sso/exchange    Redis GETDEL ticket:{t}（原子取并删，一次性）
                                   → 签发 agent token；前端立刻用 history.replaceState 去掉 URL 中的 ticket
```
- 登录安全：短信验证码限频（Redisson RateLimiter）、失败 5 次锁定 15 分钟 + 滑块验证码、导入教师 `pwd_reset_required=1` 首登强制改密（PRD 2.1 ➕ P0）。
- 身份撤销（PRD 8.3）：离职/转班/解绑时，发 `IdentityRevokedEvent` → 踢掉该身份的所有会话 + 让该身份签发的下载签名 URL、导出文件失效（导出文件记录 `identityId`，下载时校验）。

### 3.2 多租户与数据权限（PRD 8.2 R2、R7、R8）

- **租户隔离**：业务表统一带 `tenant_id`，MyBatis-Plus `TenantLineInnerInterceptor` 自动追加条件；平台公共数据（平台资源、题库、字典）`tenant_id = 0`，用白名单表忽略。
- **数据范围**：在 RuoYi 的「全部/本部门/仅本人」基础上扩展为教育场景的 7 级：

| dataScope | SQL 条件来源 |
|---|---|
| 全部 | 不加条件（平台管理员） |
| 区域 | `school.area_code IN (...)` |
| 本校 | `tenant_id = ?` |
| 本年级 | `grade_id IN (身份管理的年级)` |
| 本学科组 | `subject_id = ? AND grade_id IN (...)` |
| 本班 / 所教班级×学科 | `(class_id, subject_id) IN (任教关系)` |
| 仅本人 | `student_id = ?` 或 `create_by = ?` |

- 实现：自定义注解 `@DataScope(scope = CLASS_SUBJECT, classAlias = "h", subjectAlias = "h")`，插件根据 `IdentityContext` 拼接；任教关系缓存在 Redis，身份变化时失效。
- **越权防护（R8）**：所有接口都必须有 `@SaCheckPermission`，网关层对管理端路径做第二道校验；用 ArchUnit 写一条架构测试：「Controller 中没有权限注解的公开方法必须显式标 `@Anonymous`」，在 CI 里卡住（顺带解决 PRD 10.2.4「使用数据统计无权限码」）。
- **403 统一处理（R9）**：全局异常处理返回 `{code: 403, msg: "当前身份无权限，请联系学校管理员", applyUrl}`，前端统一弹窗。

### 3.3 金币账户与 AI 计费（PRD 2.4、11.1、D4）——最核心的一块

**表设计**：
```sql
account(user_id PK, balance, frozen, version, ...)                       -- 余额与冻结
coin_ledger(id, user_id, biz_type, biz_id, task_id, direction, amount,
            balance_after, status, idem_key UNIQUE, created_at)            -- 只增不改
ai_task(task_id PK, user_id, identity_id, agent_code, est_amount,
        frozen_amount, actual_amount, status, parent_task_id, ...)       -- 任务主表
```

**流程（冻结 → 执行 → 结算）**：
```
1. 提交：生成 taskId；校验余额(balance - frozen >= 预估)；不足直接返回，不建任务
2. 冻结：UPDATE account SET frozen = frozen + :est WHERE user_id=? AND balance - frozen >= :est
        （单条 SQL 原子判断，不需要先查再改）；写流水 FREEZE，idem_key = taskId:FREEZE
3. 执行：调用模型/工具；每个出口都必须落到 4 的某个分支（try/finally 保证）
4. 结算（同一事务）：
   成功       → 实扣 min(实际, 预估)，解冻全部，写 DEDUCT + UNFREEZE
   失败/空结果/审核拦截 → 只解冻，写 UNFREEZE，ai_task.status=FAILED_NO_CHARGE
   用户中止   → 按已生成比例计费，<10% 免费
   批量部分成功 → 按成功子任务数计费
5. 兜底：RocketMQ 延迟消息（如 30 分钟）检查任务，仍处于冻结的强制解冻
6. 对账：每日任务核对 ai_task 与 coin_ledger（同一 taskId 金额一致），差异进运营后台待处理
```
- **幂等**：`idem_key` 唯一索引兜底；`/ai/coinFlow/{id}/retry` 只能重放同一个 taskId 的结算，不会产生第二笔 DEDUCT（PRD 7.1 ⚠️ 流水重试）。
- **热点账户**：单个用户并发不高，行锁足够；学校套餐账户（PRD 2.4「学校批量授权」）可能热点，用「子账户分桶」或 Redis 预扣 + 异步落库。
- 学校套餐抵扣顺序：免费额度 → 学校套餐 → 个人金币，在 `jb-account` 的 `ChargeRouter` 里统一决定。

### 3.4 AI 智能体平台（PRD 7、10.2.4、15）

```
请求 → AgentController(SSE) → AgentRuntime
         ├─ 1. 预检：敏感词(输入) → 计费冻结 → 限流（用户/学校/智能体三级）
         ├─ 2. 组装：Prompt 模板(按版本/灰度) + 会话记忆 + RAG 检索 + 工具清单
         ├─ 3. 调用：ModelRouter → 主模型；超时/报错 → 备用模型（Sentinel 熔断）
         ├─ 4. 工具：题库检索 / 资源检索 / 学情查询（Spring AI @Tool，按身份数据权限）
         ├─ 5. 输出：流式推送；输出敏感词过滤；追加「内容由 AI 生成」标识
         └─ 6. 收尾：写消息与 token 用量 → 结算 → 调用日志 → 发 AiTaskFinishedEvent
```
- **模型抽象**：Spring AI `ChatClient`，各厂商通过 OpenAI 兼容端点接入；模型配置存库（智能体 → 主/备模型、温度、最大 token、超时），运营后台热更新。
- **工具故障不扣费**：工具调用异常要向上传成「系统失败」分类，而不是让模型生成一段「出现技术故障」的正常回复后照常扣费（这正是 PRD 实测缺陷 532 → 525 的根因）。
- **长任务（PPT、批量批改）**：提交后返回 taskId，进入 RocketMQ 队列由 worker 执行，前端通过 WebSocket/轮询看进度；失败子任务可单独重试。
- **PPT 生成**：模型输出结构化 JSON（大纲 → 每页标题/要点/配图建议），用 Apache POI 套模板渲染 `.pptx`，存 OSS 后交给 WPS WebOffice 预览/编辑；A 主站「智能备课」和 B 平台「PPT 生成」**共用这一个引擎**（PRD 15 打通需求）。
- **知识库 RAG**：上传 → Tika 解析 → 按段切分 → Embedding → 写 Milvus（metadata 带 `kbId/tenantId/identityId`，检索时强制过滤）；解析状态机：上传中 → 解析中 → 向量化中 → 可用 / 失败。
- **作文/试卷批改**：图片 → `jb-recognize` OCR → 文本 + 评分 Prompt → 结构化评分 JSON（用 JSON Schema 约束输出）→ 若关联学生则写入 `jb-learning`。
- **Prompt 管理**：`prompt_template(agent_code, version, content, gray_ratio, status)`，按用户 ID 哈希灰度，可一键回滚。
- **调用日志**：异步写入（MQ → Doris），记录用户、智能体、模型、token、耗时、成本、结果分类，供「使用数据统计」和效果评测。

### 3.5 资源、题库与检索（PRD 3.2–3.9）

- 资源与试题主数据在 MySQL，变更通过 Canal / MQ 同步到 Elasticsearch；搜索中心、筛选、排序全部走 ES。
- 教材目录树、知识点树：MySQL 闭包表或 `path` 物化路径，整树缓存到 Redis。
- **智能组卷**：输入知识点、难度分布、题型题量 → ES 召回候选 → 贪心/遗传算法满足约束 → 去重（同源题、近似题用 SimHash）；做成独立 `PaperAssembler` 组件，后面 AI 出题入库后同样参与组卷。
- 下载防爬（PRD 13）：Redisson 按用户/IP 限流；下载走短时签名 URL；付费资源 `checkPay` 走 `jb-account` 校验。
- 店铺交易（D7 未定）：订单、分账、提现单独放在 `jb-account` 的交易模块，首期可通过开关隐藏。

### 3.6 考试、扫描与阅卷（PRD 6、11.5）

```
扫描客户端(Win) ──批量上传图片(OSS直传)──► jb-exam 建扫描批次
      │                                       │ MQ: ScanBatchUploaded
      ▼                                       ▼
                                   jb-recognize(Python)：定位点校正 → 识别学号 → OMR 客观题
                                   → 切主观题区域图 → 结果回传 MQ: RecognizeDone
                                              │
                                              ▼
                        jb-exam：入库答卷；学号缺失/冲突 → 「异常卷」队列；
                        客观题自动判分；主观题生成阅卷任务
                                              │
          阅卷老师「下一份」：Redis List/ZSET 按题组分发 + Redisson 锁防重复领取
          提交分数 → 进度 WebSocket 推送 → 全部完成 → 状态机转「阅卷完成」
```
- **状态机**：作业（纸质/线上）和考试分别建状态机（PRD 11.5 A/B/C），转移表放在代码里并配单元测试；每次转移写 `state_change_log`（谁、何时、从哪到哪、原因）。
- **答题卡版本**：`sheet_version` 不可变，一旦有扫描记录即锁定；改题生成新版本（PRD D5）。
- **成绩发布与更正**：发布、撤回、更正都是事件 → 消息中心给学生/家长发通知；发布后改分保存更正记录并自动通知（PRD D2）。
- **峰值**：考试季扫描集中，`jb-recognize` 按队列积压自动扩容（K8s HPA + KEDA 读 RocketMQ 积压量）。

**手册截图补充的识别要求**（来自《智教智学使用手册》174 张配图，对识别服务的工作量影响最大）：

| 识别对象 | 手册中的实际形态 | 技术要求 |
|---|---|---|
| 页面定位 | 四角黑色定位块 + 右上角二维码；手册说明「定位块坏一个仍可识别，二维码坏了就无法识别」 | 二维码里要编码「教辅/答题卡 ID + 页码」；透视校正允许缺 1 个定位点 |
| 学号 | **手写数字填在方框里**（5–6 位），不是涂卡；答题卡另支持涂填 / 手写 / 条形码三种考号版式 | 手写数字识别（MNIST 类模型 + 学校名单校验），识别出的学号不在名单里 → 进入「异常卷」 |
| 客观题 | 教辅类作业是**学生在括号里手写字母**（A/B/AD…）；答题卡是涂卡 | 两套识别：手写字母 OCR（含多选、涂改判断）和 OMR 涂卡 |
| 主观题得分（先阅后扫） | 教师用**红笔**在「得分」框写分数，可有小数（6.5、22.5）；红笔涂改后在下方重写 | 按颜色分离红笔 → 手写数字和小数点识别；识别置信度低的进入人工复核 |
| 对错号 | 教师在题旁打 ✓ / ✗ / 半对 | 对错号检测（目标检测模型），用来辅助判分 |
| 作文 | 语文方格稿纸手写、英语横线手写 | 中文 / 英文手写 OCR → 再交给大模型评分；页面要提示「字迹潦草可能影响识别」 |
| 教辅页 | 扫描件类型可选「教辅」：印刷好的练习册页面，扫描后直接识别出题目区域 | **需要「教辅页面模板库」**：每本教辅每一页的题号、答案区和得分框坐标、标准答案，按二维码查找。这是独立的数据生产线（内容中台录入） |

**异常卷处理**（手册图 139–145）：左侧「试卷有误列表」按原因分组（学生不存在、学号缺失），每份卷子按页码成对展示（1,2 / 3,4），可以翻正反面。教师按姓名或学号搜索后点「分配给该考生」，系统重新归档并重新计算分数。后端需要 `scan_page → answer_sheet → student` 的可重新绑定关系，重新绑定要触发重新判分事件。

**扫描客户端接入**（手册图 2、问题 3）：现网用 **Dynamsoft Web TWAIN 本地服务**（`DynamsoftServiceSetup.msi`）加扫描仪 TWAIN 驱动（华高 / 松下 KV-SL1077），浏览器页面调用本机服务。手册要求用户在 `chrome://flags` 里关闭 `block-insecure-private-network-requests`，这说明网页在访问本机的 HTTP 服务时被 Chrome 的「私有网络访问」策略拦截了。重做时：
- 本地扫描服务改用 HTTPS（本机证书）并返回 `Access-Control-Allow-Private-Network` 响应头，不能再让用户改浏览器 flag；
- 或者做一个轻量桌面扫描客户端（Java + JavaFX / Electron，通过 TWAIN 桥接），直接上传 OSS，网页只看进度；
- 扫描设置（纸张 A4/A3/B5/B4/16K、扫描件类型教辅 / 答题卡、是否分配给学科教师）存到用户配置，手册写的是「设置一次后续不用再设」。

### 3.7 学情分析（PRD 6.6、6.10、D3）

- 业务库只存原子事实：答卷、逐题得分、知识点映射；学情指标不在业务库实时 SQL 里聚合。
- 流程：成绩发布事件 → 同步明细到 Doris（Flink CDC 或 Routine Load）→ 计算任务按 D3 统一口径生成班级/年级/学生/知识点各层指标 → 结果表回写或直接由报表 API 查询 Doris。
- 指标口径做成**代码化的指标定义**（一个指标一个类 + 单元测试），避免各报表各算各的。
- 手册截图里已经能看到口径不统一和计算错误，重做时必须用测试用例卡住：
  - 成绩分档的口径有两套：手册文字写「满分四等分（0–25 不合格…）」，页面图例是「优秀 85–100% / 良好 75–85% / 合格 60–75% / 不合格 <60%」，两者不一致；
  - 个人作业详情里「个人得分率 141.05%」超过 100%；题型失分表中解答题「我的得分 70 / 总分 10，失分 −60」；
  - 错题本列表有两列都叫「是否制卡」。
- 手册给出的规则可以直接写成代码：临界生 = 及格线上下 5%；成绩下降 = 近三次考试连续下降（不足三次按最近两次）；题目得分率 = 该题均分 ÷ 该题满分；章节 / 知识点错误率 = 错题数 ÷ 该章节（知识点）题数。
- 报表清单（全部要支持「图表 / 表格」切换和导出）：
  - 作业维度：平均得分率对比、成绩分档、成绩综合报表、题目得分率对比、知识薄弱点热力图、试题平均分对比、题型雷达、典型错题排行；
  - 年级维度：班级成绩趋势、学业等级分布、临界生、优秀生与学困生；
  - 班级维度：前 10 名排名动态、需关注学生、错题列表、简单丢分题、章节 / 知识点错误率、学生正答率、作业提交率；
  - 个人维度：成长曲线、错题、优势得分题、个性化作业。

### 3.7.1 作业讲评与大屏演示（手册 5.4）

- 讲评页按题型、得分率区间、「只看重点题」筛选；每道题显示班级 / 年级得分率、章节、知识点，可以设为重点。
- 大屏模式：放大、缩小、切题、显示或隐藏作答数据、答案解析、**类题练习**（按知识点推荐同类题，走 ES 相似题检索）、题目列表（按得分率着色）、切换大屏配色、**手写批注**（画笔颜色和粗细、橡皮擦、清屏）。手写批注是纯前端 Canvas，不用存后端；如果要「保存讲评板书」，再加一个 OSS 存储即可。

### 3.7.2 题库录入与答题卡编辑器（手册第 7、8 章）

- **批量导入题目**：「输入区」是富文本编辑器（支持公式），用标记切分结构：`【题型】【难度】【题文】【选项】【答案】【解析】【题组】【题组小题】【题组结束】`。右侧「检查区」实时预览解析结果，确认后保存。后端实现成一个**标记文本解析器**（状态机逐段解析），每个学科的题型白名单单独配置（语文、数学、英语、物理、化学…各不相同）。也支持下载 Word 模板导入，用 POI 解析。
- **单题录入**：题型、题组、难度、题文、每行选项数、选项（可增删）、解析；公式统一存成 LaTeX / MathML，渲染用 MathJax / KaTeX。
- **答题卡编辑器**：题卡样式（纯题卡 / 题卡合一）、纸张（A4 / A3）、栏数、阅卷方式（先扫后阅 / 先阅后扫）、考号版式（涂填 / 手写 / 条形码）、客观题竖排、客观题合并批阅、红色答题卡、注意事项。题目块包括客观题（单选 / 多选 / 判断，从第几题到第几题、每题分值、选项数，可以分段添加）、填空题、解答题、题组、语文作文（方格，最少字数、每 100 字标记）、英语作文（行数，题型可选书面表达 / 单句写作 / 阅读表达 / 应用文写作）。
  - 存储：答题卡布局用 JSON 描述，后端用 **PDFBox / OpenPDF 按 JSON 生成 PDF**，同时生成「识别坐标模板」交给 `jb-recognize`。两者必须同源，否则识别区域会错位。
  - 规则：一张 A4 只能有一个二维码（手册提示双面打印会出现两个二维码导致识别失败）；已经下载并扫描过的答题卡不允许再编辑（对应 PRD D5 的版本锁定）。
- **试卷 → 答题卡**：试题篮组卷后可以设置分数、做试卷分析、保存到目录，再一键生成答题卡和下载试卷（Word / PDF）。
- **错题本**：按日期、学段学科、多个班级、学生、试卷筛选错题 → 按题型筛选、按得分率区间筛选 → 加入试题篮 / 插入同类题 → 生成错题本（可上移、下移、删除，查看答案解析）→ 预览、下载、制作答题卡。

### 3.7.3 学校基础数据（手册第 4 章）

- 学生：姓名、性别、学籍号、学号（系统生成 5–6 位，校内唯一，学生写在试卷上）、**卡号**（用途手册没写，推测是校园卡或考号，需要确认）。导入模板字段：姓名、年级、班级、性别、入学日期、学籍号。
- 教师：导入模板字段为姓名、手机号、学年、年级、班级、学科（可多选，比如「初中-语文;初中-数学」）、是否年级主任、是否班主任；手动添加时的**角色有五种：任课教师、班主任、年级主任、学科组长、校领导**。PRD 里把「教研组长」标成「代码存在 / 建议新增」，实际上「学科组长」和「校领导」角色**已经实现**，需要回改 PRD。
- 导入走「上传 → 异步校验（重名、学号冲突、手机号已存在）→ 预览错误行 → 确认入库」，用 EasyExcel 流式读取，避免大文件撑爆内存。
- 默认密码 123456 的问题依旧：导入时 `pwd_reset_required=1`，首登强制改密。

### 3.7.4 其他从截图中确认的入口

- 右侧悬浮栏有**「手机批阅」**、QQ、使用说明、下载驱动、人工客服、问题反馈。手机批阅说明阅卷有移动端（H5 或小程序），阅卷接口要按「移动端也能用」来设计：分页领取任务，按单题切图返回。
- 智能组卷会跳到一个独立产品**「举一反三」**（首页 / 举一反三 / 选题出卷 / 快速出卷 / 精准出卷 / 我的）：按知识点树选知识点 → 设难度 → 设各题型题量 → 生成试卷 → 换题、换序、暂存、下载、看难度分布。这是第四个子系统，统一账号和 SSO 要把它也覆盖进去。
- 不同截图里的顶部菜单不一样：有一版是「作业列表 / 学情分析 / 错题重练 / 题库中心 / 作文批改 / 数据中心」，另一版是「批阅中心 / 学情分析 / 错题重练 / 智能组卷 / 制作答题卡 / 云题库 / 数据中心」。说明菜单按租户或版本配置，印证了「菜单由后端下发 + 租户套餐控制功能开关」的设计。
- 截图中出现内网地址 `192.168.6.77:8085` 和书签「测试环境77」，这是测试环境，不能当作私有化部署的证据。
- 「重置学情」= 删除该考试的计算结果并重新触发计算，操作写审计日志。

### 3.8 学生端、家长端与消息（PRD 9.7、9.8、11.10）

- 学生端、家长端共用后端服务，通过身份类型和 dataScope「仅本人 / 已绑定孩子」隔离。
- 家长绑定：学号 + 姓名 + **学校下发的绑定码或班主任审核**（不能只靠学号姓名），一个孩子最多 N 个家长。
- 微信小程序：WxJava 登录 → 与 User 关联手机号；通知走小程序订阅消息。
- 消息中心：`message(收件身份, 类型, 业务id, 已读)` + WebSocket 实时推送 + 微信/短信渠道路由；业务方只发 `NotifyEvent`，不直接调渠道。
- 学生端 AI：同一个 AgentRuntime，但用「学生模式」策略：更严格的敏感词、禁用部分工具、限制每日次数。

### 3.9 运营后台与审核（PRD 10.2）

- 统一审核流：`audit_task(biz_type, biz_id, 状态, 机审结果, 人审人)`；征集、店铺、论坛、评论、举报、AI 内容都接入；机审用内容安全 API + 本地敏感词（DFA/AC 自动机）。
- 字典、教材目录、知识点、智能体、Prompt、计费规则都在运营后台维护，修改后发配置变更事件刷新缓存。
- 人工调账必须走审批（PRD D4）：申请 → 审批 → 执行，生成 `ADJUST` 类流水。

## 4. 非功能实现要点（PRD 13）

| 要求 | 实现方式 |
|---|---|
| 全站 HTTPS | 入口 Ingress 统一证书；HSTS；禁止 http 回源 |
| 统一错误码，不暴露内部信息 | `GlobalExceptionHandler`：业务异常返回业务码；未知异常只返回「服务繁忙」+ traceId，详情只进日志 |
| 敏感数据 | 手机号、学生姓名、身份证等用 MyBatis TypeHandler 做字段级 AES 加密 + 查询用哈希列；日志脱敏 |
| 操作审计 | `@Log` 注解 + 异步写操作日志；成绩、调账、权限变更单独写审计表，保留 ≥ 180 天 |
| 性能目标 | 首页聚合接口走 Redis 缓存 + 静态化；AI 首 token < 3s 靠流式 + 模型就近；PPT 生成 < 60s 靠异步任务 + 进度推送 |
| 降级 | 学科网、WPS、模型厂商都包在 Sentinel 资源里，熔断时返回明确的降级提示 |
| 可用性 | 核心服务 ≥ 2 副本；MySQL 主从 + 半同步；Redis 哨兵/集群；RocketMQ 双主双从 |
| 测试 | 单元测试（JUnit 5 + Mockito）；集成测试用 Testcontainers 起 MySQL/Redis/RocketMQ；计费、状态机、数据权限必须有测试覆盖；PRD 第 17 章 17 条验收用例转成自动化接口测试 |

## 6. 风险与应对

| 风险 | 影响 | 应对 |

| 第 16 章 D1–D4 没定就开发 | 计费、学情口径、作业学年返工，影响数据模型 | 第 0 步就拍板，并把规则写成测试用例 |
| 答题卡识别准确率 | 阅卷全链路不可用 | 识别服务单独立项，先对接现有识别能力或成熟第三方，Java 侧只依赖 MQ 契约，方便替换。注意现网主要识别的是**手写**学号、手写选项字母和红笔分数，不只是涂卡，难度和工作量都高得多 |
| 教辅页面模板库 | 「教辅」类作业扫描后无法定位题目 | 每本教辅、每一页都要录入题目区域坐标和答案，是持续的内容生产成本；内容中台要配套标注工具 |
| 浏览器访问本机扫描服务受限 | 用户必须手动修改 Chrome flag，后续 Chrome 版本可能彻底封掉 | 本地服务改 HTTPS + Private Network Access 响应头，或者改成桌面扫描客户端 |
| 大模型成本与稳定性 | 扣费纠纷、毛利 | 模型主备路由、按智能体设预算上限、调用日志算单次成本、失败不计费 |
| 学生个人信息合规 | 监管风险 | 字段加密、最小化收集、家长授权记录、数据导出审批、私有桶 + 短时 URL |
| 与现网系统并存迁移 | 数据不一致 | 若是在现网基础上重构：按服务逐个替换（绞杀者模式），网关按路径切流，老库数据用 CDC 双写校验 |
| 微服务过多导致运维成本高 | 交付变慢 | 严格控制在 8+1 个服务；小团队可先做「模块化单体」（同样的模块划分，单进程部署），二期再拆 |

## 7. 待确认事项（技术侧）

1. **重建还是承接**：是基于现网代码重构，还是全新开发？影响是否保留现有接口前缀和数据库结构。
2. **部署方式**：公有云 SaaS，还是需要支持学校/区域**私有化部署**？私有化会影响中间件选型（OSS → MinIO、云 OCR → 本地模型）。
3. **大模型供应商**：使用哪些厂商、是否需要本地部署开源模型（影响 GPU 预算和 ModelRouter 设计）。
4. **扫描识别**：沿用现有识别引擎，还是自研？
5. **团队规模与技术储备**：决定「8 个微服务」还是「模块化单体起步」。

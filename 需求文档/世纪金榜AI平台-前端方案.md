# 世纪金榜AI 教学平台 · 前端方案

## 方案依据

- 《功能逻辑需求文档》v1.2（下称 PRD）
- 《Java 技术路线》
- `jinbang-platform` 后端（共 266 个接口，Swagger 地址 `/swagger-ui.html`）

## 状态

**已决策（2026-11-20），按建议执行**：主站与 AI 平台合并；学生端、家长端用 uni-app 同时出小程序和 H5；扫描客户端用 Tauri；不等设计稿，用 Element Plus 默认主题加品牌色起步。

## 0. 结论先行

| 决策 | 建议 | 理由 |
|---|---|---|
| 技术栈 | **Vue 3 + TypeScript + Vite + Element Plus** | 现网就是 Vue（技术路线 2）。Element Plus 的表格和表单最适合教务、阅卷这类重数据页面 |
| 学生端、家长端 | **uni-app（Vue 3）**：一套代码出微信小程序和 H5 | 家长端现网是小程序。学生在校用 H5，在家用小程序，两种都要 |
| 工程组织 | **pnpm monorepo**：4 个应用共用 6 个包 | 接口类型、登录身份、题目渲染、图表在各端都要用，必须只维护一份 |
| 主站与 AI 平台 | **合并成一个教师 Web 应用**，AI 作为其中的「AI 工作台」模块（见 8.1） | 后端已经是同一套账号、计费和题库。分成两个站只会把 PRD 指出的「两套生成器、两份数据」在前端再做一遍 |
| 接口调用 | 由后端 OpenAPI **自动生成 TypeScript 类型和请求函数** | 后端接口变了，前端编译时就会报错，不靠人工对字段 |
| 权限 | 后端下发路由 + `v-perm` 按钮指令 + 统一的 403 页 | 对应 R1、R8、R9；前端只负责「藏」，真正的拦截在后端（已实现） |

**最难的 5 个组件**：

1. 答题卡编辑器与打印
2. 阅卷工作台（原卷切图 + 批注）
3. 题目编辑器（公式、表格、图片）
4. 学情报表（ECharts）
5. AI 流式对话

这 5 个都放进共享包，单独排期、单独验收。其余大约 80% 是标准的列表和表单页面。

### 1.1 teacher-web 教师 Web

**对象：** 游客教师、任课教师、班主任、年级主任、学科组长、校领导、区域教研员。

**菜单：** 首页 / 资源中心 / 教学中心 / 考试阅卷 / 学情分析 / AI 工作台 / 个人中心。

### 1.2 admin-web 管理后台

**对象：** 学校管理员、平台运营（超管、运营、审核、财务、客服）。

**说明：** 同一个应用，按当前身份下发「学校后台」或「运营后台」两套菜单。

### 1.3 student-app 学生端、家长端

**对象：** 学生、家长。

**说明：** 一套 uni-app 代码，按身份切换首页。

- 学生：作业、成绩、错题、AI 学伴、学海共渡；
- 家长：孩子列表、成绩、学情、通知、家长助手。

### 1.4 screen-web 大屏

**对象：** 学校、教室一体机。

**内容：**

- 学校可视化大屏；
- 讲评的「大屏演示」（PRD 6.5），以 1920×1080 为基准等比缩放。

### 1.5 scan-client 扫描客户端

**对象：** 学校扫描员、教师。

**说明：** 用来解决 AC-20（不改 Chrome flag 也能扫描），见 4.6。

### 1.6 不单独做的应用

| 内容 | 处理方式 |
|---|---|
| AI 平台独立站 | 并进教师 Web；保留原 agent 域名，指向教师 Web 的 `/ai` 路由，兼容老链接 |
| 授课客户端 | 先做 **Web 版授课兜底**（PRD 4.2 ➕P1）：全屏放映 PPT 转图、计时器、随机点名。原生客户端和手机遥控以后再评估 |

## 4. 关键组件设计

### 4.1 答题卡编辑器与打印（packages/sheet）

**题目块：**

- 客观题：从第 X 题到第 Y 题，每题 N 分，M 个选项；
- 填空、解答、题组；
- 语文作文：格子数、最少字数标记；
- 英语作文：行数。

**卡头：** 学校 / 姓名 / 班级 / 考场、学号区（手写 / 涂填 / 条形码，默认 6 位）、二维码、四角定位点。

**排版：**

- 版面模型就是后端的 `blocks` JSON；
- 前端用 HTML/CSS 按毫米排版，A4 和 A3 两种纸张；
- 打印走浏览器打印，`@page` 设边距为 0。

**规则（AC-04）：**

- 「下载 / 打印」先调用 `/download`，冻结当前版本，二维码里写入版本号；
- 修改已冻结的版本时，提示「将生成 v{n+1}」。

**打印规则：** 一张 A4 只印一份答题卡，打印预览里强制提示。

**风险：** 浏览器打印的位置精度要和识别服务对齐。建议版面确定后，由后端用 PDFBox 生成 PDF 作为标准件，前端只负责编辑和预览（见 7.1）。

### 4.2 阅卷工作台（packages/marking）

**布局：**

- **左侧：** 题号切换、查看答案、学生列表（未批完的标红）。
- **中间：** 原卷切图，支持缩放和正反面切换；Konva 批注层（文本、对、错、半对、画笔、橡皮）。
- **右侧：** 分数输入、满分 / 零分快捷键、分步赋分、自动提交、提交后自动取下一份（调用 `/marking/next`）。

**交互：**

- 键盘优先：数字键输分，Enter 提交，`←` / `→` 回批；
- 越界分数在前端提前拦截，后端仍会返回 3002（AC-18）；
- 成绩发布后改分，必须填写更正原因。

**性能：** 下一份的切图提前预取，保证翻页零等待。

### 4.3 题目编辑与批量录题（packages/question）

**题目编辑器：** Tiptap，支持公式（MathLive）、表格、图片。

**批量录题：**

- 左侧输入区按【题型】【题文】等标记录入，粘贴 Word 时保留公式图片；
- 右侧检查区调用 `/questions/import/preview` 实时预览；
- 错误题号可以点击跳回输入区对应位置。

### 4.4 学情报表（packages/charts）

**通用交互（PRD 6.6）：** 每个报表都有「?」口径说明、图表 / 表格切换、下载。

**口径一律以后端为准：** 前端不做任何得分率计算，避免两套口径。

### 4.5 AI 流式对话（packages/ai-chat）

**接收方式：**

- 流式接口 `/api/ai/chat/stream` 是 POST 请求，`EventSource` 不能发 POST；
- 所以用 `fetch` + `ReadableStream` 解析 SSE 的 `start`、`delta`、`done`、`error` 四种事件。

**交互：**

- 「停止生成」调用 `/tasks/{id}/stop`；
- 提交前显示「预计消耗 N 币」（`/api/ai/estimate`）；
- 结果下方显示「本次消耗 / 未扣费」和「内容由 AI 生成，仅供参考」；
- 失败项提供「重试」，重试不重复扣费。

**渲染：** Markdown、KaTeX、代码高亮、ECharts 代码块。

### 4.6 扫描客户端（解决 AC-20）

**问题：** 网页访问本机扫描服务会被 Chrome 的 Private Network Access 拦截，现网让用户手动改 flag，以后的 Chrome 版本可能彻底封掉。

**方案：**

- 用 **Tauri** 做一个桌面壳，内嵌 teacher-web 的扫描页面；
- 扫描仪由壳直接驱动（TWAIN，可以继续用 Dynamsoft 的授权，或用 Rust 的 TWAIN 绑定）；
- 扫描图片由壳上传给识别服务；
- 网页不再访问本机端口，PNA 问题从根本上消失。

**备选：** 不做桌面客户端，就把本机扫描服务改成 HTTPS，并返回 `Access-Control-Allow-Private-Network: true` 响应头。这条路依赖扫描插件厂商配合。

## 7. 前端开工前后端需要补的接口

在逐个核对 266 个接口时，发现以下缺口。

1. **原卷图片访问：** 答卷的 `images` 现在只存了识别服务回传的文件名，没有给前端看图的接口。需要：
   - 识别服务把图片写入存储；
   - 后端提供带鉴权的短时图片链接；
   - 如果要做切图，还需要题目区域的坐标。
2. **按 ID 批量取姓名：** 未交名单、客观题矩阵、成员列表等接口只返回 `studentId` / `userId`。需要一个按 ID 批量取姓名的接口（带数据权限）。
3. **答题卡 PDF：** 第 4.1 节建议由后端用 PDFBox 生成标准 PDF。目前后端只返回版面数据。
4. **课件预览：** PPTX / DOCX 需要后端转成图片或 PDF，或者接入 WPS WebOffice。
5. **教师选择器：** 集体备课选成员、阅卷分配都要「本校教师列表」。现有接口要求 `school:teacher:manage` 权限，需要一个只读的精简版本。
6. **我的身份信息：** 学生或家长身份下需要「当前学生是谁」。现在只能通过 `resolveStudent` 间接得到，建议增加 `/api/portal/me`。

这 6 项后端工作量大约 1 周，可以在 F0 期间完成。
